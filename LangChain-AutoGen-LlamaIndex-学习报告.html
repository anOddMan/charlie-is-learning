框架对比学习报告

全文总结：LangChain 是 LLM 应用开发的事实标准，生态最广但学习曲线较陡； LlamaIndex 在 RAG / 数据检索场景一骑绝尘，是文档密集型应用的首选； AutoGen 以"多智能体对话协作"为核心范式，已并入 Microsoft Agent Framework。 建议以 LangChain → LangGraph → 配合 LlamaIndex（RAG 增强） 为主线， 辅以 AutoGen 理解多智能体协作思想，按"基础→RAG→Agent→生产部署"四阶段学习。

🦜 二、LangChain 深度分析

LangChain 由 Harrison Chase 于 2022 年创建，是 LLM 应用开发领域最成熟、生态最广的框架。 2025–2026 年已演进至 v1.x，核心 API 统一为 create_agent()，底层的编排引擎完全基于 LangGraph（有向图状态机）。

🏗️ 核心架构（LangChain 全家桶）

🔗 langchain-core

基础抽象层：LCEL（LangChain 表达式语言）、Runnable 协议、消息类型、工具定义。所有上层包共享这一层。

🧠 langchain-openai / anthropic

模型提供商包。支持 OpenAI、Anthropic、Google、AWS Bedrock、Ollama 等 20+ 模型，一行代码切换。

📊 LangGraph

状态图编排引擎。节点的有向图 + 条件边 + 检查点持久化，支持循环、分支、人工介入、时间旅行调试。

🔭 LangSmith

可观测性平台。全链路追踪、A/B 测试评估、成本监控、Agent 舰队管理。可跨框架使用。

💻 代码示例

PYTHONagent_basic.py — v1.x 统一 API
# LangChain v1.x — 一条链搞定 RAG + Agent
from langchain import create_agent
from langchain.tools import tool

@tool
def search_knowledge_base(query: str) -> str:
    """搜索公司内部知识库。输入自然语言查询。"""
    return retrieve_from_vector_db(query)

agent = create_agent(
    model="claude-fable-5",          # 可任意切换模型
    tools=[search_knowledge_base, web_search],
    system_prompt="你是企业内部助手，优先查知识库再联网搜索。",
    middleware=[ModelFallbackMiddleware()],  # 新特性：中间件
)

result = agent.invoke("公司Q3的营收目标是多少？")

🦙 三、LlamaIndex 深度分析

LlamaIndex（原 GPT Index）由 Jerry Liu 创建，最初专注于数据连接与检索。 经过 v0.10 重大重构后，已进化为具备 Agent 能力的数据驱动框架——在 RAG 场景下，其精致度和性能往往优于 LangChain。

🏗️ 核心架构

🔑 关键特性

📄 LlamaParse

专业文档解析器，PDF/PPTX/Word 复杂排版解析能力业界领先，支持表格、图片提取。

🧩 LlamaHub

数据加载器市场，300+ 连接器覆盖数据库、SaaS 工具、文件格式。

🔀 查询路由

RouterQueryEngine 智能将查询路由到最合适的索引（向量库/SQL/知识图谱）。

📊 Workflow 引擎

事件驱动的 Agent 设计，@step 装饰器语法简洁直观。

💻 代码示例

PYTHONrag_llamaindex.py — 典型 RAG 流水线
from llama_index.core import SimpleDirectoryReader, VectorStoreIndex
from llama_index.core.node_parser import SentenceSplitter

# 1. 加载文档（支持 PDF、Word、Markdown 等 20+ 格式）
documents = SimpleDirectoryReader("./knowledge_base").load_data()

# 2. 智能分块（保持语义完整性）
parser = SentenceSplitter(chunk_size=1024, chunk_overlap=200)
nodes = parser.get_nodes_from_documents(documents)

# 3. 构建向量索引
index = VectorStoreIndex(nodes)

# 4. 查询（支持混合检索 + 重排序）
query_engine = index.as_query_engine(
    similarity_top_k=8,
    node_postprocessors=[SentenceTransformerRerank(top_n=3)],
)
response = query_engine.query("2025年Q3的营收目标是多少？")

💡 关键洞察：LlamaIndex 的 chunk_size 建议：散文 400–800 tokens，代码 80–160 tokens， overlap 10–25%。推荐使用混合检索（BM25 + 向量）+ 交叉编码器重排序，Top-5 准确率可达 92%+。

🤖 四、AutoGen 深度分析

AutoGen 由微软研究院于 2023 年底发布，核心思想是将"对话"作为多智能体协作的基础机制。 不同角色的 Agent（规划者、编码者、评审者、执行者）通过自然语言对话来分解和执行任务。

⚠️ 重要变化（2025–2026）：2025 年 10 月，微软宣布 AutoGen 与 Semantic Kernel 合并为 Microsoft Agent Framework (MAF)。AutoGen 不再作为独立框架接收主要功能更新， 新项目建议使用 MAF。但 AutoGen 的多智能体协作思想已成为行业标准。

🏗️ AutoGen v0.4 三层架构

层级包名职责
Coreautogen-core事件驱动原语：RoutedAgent、发布/订阅消息
AgentChatautogen-agentchat高级 API：AssistantAgent、UserProxyAgent、GroupChat
Extensionsautogen-ext插件生态：OpenAI、MCP、gRPC 等

🔑 核心抽象

👤 ConversableAgent

所有 Agent 的基类。具备发送/接收消息、生成回复、调用工具、执行代码的能力。

👥 GroupChat

多 Agent 群聊容器。支持 Speaker Selection（轮流发言）、max_round 控制对话轮次。

💻 Code Executor

Agent 生成代码后在沙箱中执行，观察输出并自主修复错误（Write-Run-Fix Loop）。

🛑 Human-in-the-Loop

关键步骤暂停等待人工审批，支持人机混合协作。

💻 代码示例

PYTHONautogen_groupchat.py — 多 Agent 群聊协作
# AutoGen 经典模式：规划者 → 研究者 → 编码者 → 评审者 → 执行者
from autogen import AssistantAgent, UserProxyAgent, GroupChat, GroupChatManager

planner    = AssistantAgent(name="planner",    system_message="拆解任务为子步骤。")
coder      = AssistantAgent(name="coder",      system_message="编写 Python 代码实现。")
reviewer  = AssistantAgent(name="reviewer",  system_message="审查代码，找问题。")
executor  = UserProxyAgent( name="executor",  code_execution_config={"work_dir": "./workspace"})

groupchat = GroupChat(agents=[planner, coder, reviewer, executor], max_round=12)
manager  = GroupChatManager(groupchat=groupchat)

executor.initiate_chat(manager, message="写一个从 Yahoo Finance 下载股票数据的 Python 类")

⚡ 注意：多 Agent 对话会成倍放大 Token 消耗。5 个 Agent × 12 轮对话可能消耗数万 Token。 务必设置 max_round 上限，并考虑使用更便宜或本地模型来降低成本。

5.2 适合场景速查

选 LangChain 当……

✅ 需要复杂工作流编排（分支、循环、条件路由）
✅ 要在多个模型提供商间灵活切换
✅ 需要生产级可观测性（LangSmith）
✅ 团队规模 4 人以上，有工程化要求
✅ 构建通用 LLM 应用（不限于 RAG）

选 LlamaIndex 当……

✅ 核心场景是文档检索引擎（知识库、法律/合同分析）
✅ 需要处理大量非结构化数据（PDF、PPTX、网页）
✅ 对检索精度要求高（混合检索 + 重排序）
✅ 希望依赖更少、代码更简洁
✅ 团队专注 RAG 方向

选 AutoGen 当……

✅ 需要多角色协作（设计评审、编写+审查+测试）
✅ 场景是代码生成+自动执行+修复
✅ 微软/Azure 技术栈
✅ 需要人工审批节点（Human-in-the-Loop）
✅ 快速原型验证多智能体方案

5.3 技术趋势（2026 展望）

🔀 框架趋同

三者都在向 Agent 编排能力靠拢。LangGraph 的图编排、LlamaIndex 的 Workflow、AutoGen 的 GroupChat 正在以不同方式解决同一问题——多步骤智能体协调。

🔗 组合使用成为主流

生产团队常见的组合：LangGraph 做主编排 → LlamaIndex 做检索 → 底层直接调用 LLM API。 不再迷信单一框架解决所有问题。

📉 "无框架"趋势

部分大厂开始用极简自定义循环（直接 tool-calling + LLM API）替代重框架，避免版本依赖和抽象开销。

🔄 AutoGen → MAF

AutoGen 并入 Microsoft Agent Framework，.NET 生态企业用户将获得原生支持。

🗺️ 六、推荐学习路线

综合以上分析，推荐的最佳学习策略是：以 LangChain/LangGraph 为主线， 切入 LlamaIndex 补充 RAG 能力，了解 AutoGen 的多智能体协作思想。 按以下四阶段、约 8–12 周、每天 2–3 小时推进：

各阶段详细内容

🌱 Phase 1：基础筑基（第 1–2 周）

目标：脱离框架，理解 LLM 底层原理。
内容：Transformer 架构 · Tokenization (BPE/SentencePiece) · Embedding 原理 · 直接调用 OpenAI/Anthropic API · 手写多轮对话 · Function Calling 机制 · Prompt Engineering（零样本/少样本/CoT）
⚠️ 不要碰框架：先用原生 API 实现一遍，理解底层后再用框架才能事半功倍。

🛠️ Phase 2：LangChain 核心（第 3–6 周）

目标：掌握 LangChain 核心抽象与 LCEL。
内容：
• PromptTemplate → ChatModel → OutputParser 流水线
• LCEL：chain = prompt | model | parser，理解 Runnable 协议
• Memory 管理：BufferMemory / SummaryMemory / LangGraph 检查点
• Tools：@tool 装饰器 + bind_tools
• Agent：create_agent() 一站式创建
✅ 里程碑：能独立构建一个带记忆和工具的对话 Agent。

⚡ Phase 3：RAG + Agent 进阶（第 7–9 周）

目标：掌握 RAG 全流程 + LangGraph 状态机。
内容：
• RAG 全链路：加载→分割(800-1200 tokens)→嵌入→向量库→检索→生成
• LangGraph：StateGraph + Node + Conditional Edge + Checkpointer
• 对比 LlamaIndex 的 RAG 实现，理解其索引和查询路由优势
• 了解 AutoGen 的 GroupChat 多 Agent 协作模式
• 可选：CrewAI 快速尝鲜（角色驱动多 Agent）
✅ 里程碑：能用 LangGraph 构建含人工审批节点的多 Agent 工作流。

🚀 Phase 4：生产化与实战（第 10–12 周）

目标：将 Agent 从笔记本搬到生产环境。
内容：
• LangSmith 全链路追踪与评估
• 高级 RAG：混合检索、重排序、Self-RAG、多模态 RAG
• 部署：LangServe / FastAPI / Docker / K8s
• 生产最佳实践：限流、降级、语义缓存、Token 预算控制
✅ 里程碑：完成一个可部署的端到端 AI 应用。
