1 背景与核心问题

核心主张：与其为每个用例从零构建一个 monolithic AI Agent，不如构建可组合、可复用的 Skills，让通用 Agent 按需加载领域专长。

文章开篇指出当前 AI Agent 开发中的普遍误区：团队投入大量精力为每个业务场景构建独立的 Agent 系统，却忽视了这些系统之间的共通性。结果就是大量重复造轮子，每个 Agent 都从零学习领域知识，维护成本高且难以规模化。

Anthropic 的观察是：瓶颈不在于 Agent 的推理能力，而在于 Agent 缺乏在真实世界中操作所需的领域知识和流程规范。如果你需要 Agent 理解公司政策、遵循特定工作流程、使用专有工具——这些都是 Skills 要解决的问题。

💡
核心洞察：Agent 是推理引擎，Skills 是知识库。两者分离，各自独立演进。

文章引用了 AI 社区中流行的说法："Don't build agents, build skills." ——与其构建更多 Agent，不如构建 Skills，让一个通用 Agent 通过 Skills 获得无限扩展的能力。

2 什么是 Agent Skill

Agent Skill 是一个目录结构，包含指令、脚本和资源文件，Agent 可以动态发现并按需加载。文章将其比喻为"新员工的入职培训手册"——把领域专长打包成可组合的资源包。

目录结构

每个 Skill 是一个独立的目录，以下为标准化布局：

📁 my-skill/
📄 SKILL.md 必需 YAML 前置元数据 + Markdown 指令
📄 reference.md 可选 引用文档，按需加载
📁 examples/ 可选 示例文件
└── sample-output.json
📁 references/ 可选 参考资料目录
└── policy-faq.md
📁 assets/ 可选 模板和静态资源
└── report-template.md
📁 scripts/ 可选 可执行脚本
└── helper.py

SKILL.md 格式

SKILL.md 由 YAML 前置元数据（Frontmatter）和 Markdown 指令体两部分组成，中间用 --- 分隔：

SKILL.md YAML Frontmatter + Markdown Body
📋 前置元数据（Frontmatter）
name: brand-guidelines ← 标识符，小写字母+连字符
description: >- 当需要应用 Acme 公司品牌规范时使用... ← 触发条件描述（Agent 据此判断）
allowed-tools: ["Read", "Write", "Edit"] ← 允许 Agent 使用的工具
user-invocable: true ← 用户可手动触发
📝 Markdown 指令体（Body）
# 品牌规范
## 配色
- 主色: #FF6B35
- 辅助色: #2D3436
## 字体
- 标题: Montserrat Bold
- 正文: Open Sans
## Logo 使用
- 浅色背景用全彩 Logo
- 深色背景用白色 Logo
字段必需说明
name是（Claude.ai）/ 否（Claude Code）小写字母+连字符，最长 64 字符
description推荐Agent 据此判断是否触发该 Skill，最长 1024 字符
allowed-tools否允许 Agent 使用的工具列表
user-invocable否false = 仅 Agent 可自动触发
disable-model-invocation否true = 仅用户可手动触发
context否fork 表示在子 Agent 中运行
paths否Glob 模式，限定 Skill 在哪些路径下激活

3 渐进式披露（Progressive Disclosure）

这是文章强调的核心设计原则。Skill 分阶段加载信息，优化 Token 使用：

L1
元数据
~30-100 tokens
name + description
始终加载到系统提示词
L2
完整指令
< 5,000 tokens
SKILL.md 正文
触发时加载
L3
参考资料
按需
references/ 等附属文件
按需读取
L4
脚本执行
不占上下文
scripts/ 可执行代码
通过工具调用执行
设计意图：就像一本组织良好的手册——先看目录，再读具体章节，最后查阅附录。Agent 只在必要时才加载更多信息，始终保持上下文窗口的精简。

为什么重要？在大语言模型的应用中，上下文窗口是宝贵的资源。如果每个 Skill 的全部内容都加载到上下文中，几十个 Skill 就会迅速耗尽可用 Token。渐进式披露使得系统可以管理数百个 Skill，而上下文仅包含它们的 name + description。只有当 Agent 判断某个 Skill 与当前任务相关时，才会加载其完整内容。

4 代码执行

Skills 可以包含预编写的可执行脚本（Python、JS、Shell 等），这些脚本通过工具调用运行，不占用上下文窗口。这意味着 Agent 可以执行确定性操作而无需理解脚本的每一行细节。

这对需要精确性、可重复性、可审计性的操作场景非常关键。Agent 不必"猜测"如何执行某个操作，而是直接运行经过测试的脚本。

5 Skills vs MCP vs CLAUDE.md

文章澄清了 Skills 与 Anthropic 其他扩展机制的关系：

机制最佳用途加载时机
CLAUDE.md全局行为引导（始终生效的规则）始终加载
Agent Skills可复用的 SOP、领域知识、流程规范按需加载（渐进式披露）
MCP（Model Context Protocol）连接外部工具和数据源工具调用时

Skills 和 MCP 是互补关系：Skills 编码了流程性知识（怎么做），MCP 提供了外部工具接入（用什么做）。一个 Skill 可以指示 Agent 通过 MCP 工具来执行具体操作。

6 最佳实践

文章总结了以下实践建议：

实践说明
范围聚焦一个 Skill 只做一件事。互斥的行为拆分成不同 Skill
激活条件清晰用 "Use this when..." 风格写 description，包含正面 + 反面示例
渐进式设计SKILL.md 保持在 500 行以内，长规则移到 references/ 目录
评估驱动维护能力评估 + 回归测试，自动化 CI 集成
与 Claude 迭代让 Claude 帮你写和优化 Skill，形成人机协作循环
从 Claude 视角思考写 description 时考虑 Claude 何时/如何判断是否触发
安全优先仅从可信来源安装，审计代码依赖和网络连接，沙箱化脚本执行

7 开放标准与生态系统

Anthropic 将 Agent Skills 作为一个开放标准发布在 agentskills.io，允许多平台兼容。目前已被广泛采用：

Claude Code Claude.ai Claude API / SDK OpenAI Codex CLI ChatGPT GitHub Copilot Cursor VS Code Gemini CLI JetBrains Junie AWS Kiro Block Goose Microsoft Agent Framework

这种跨平台的标准化意味着：一次编写 Skill，随处可用。开发团队可以为内部工具和流程编写一套 Skills，然后在不同 AI 工具之间共享。

文章愿景：未来 Agent 能够自主创建、编辑、评估和分享 Skills。Skills 将成为 AI Agent 的"应用商店"——一个由社区驱动的知识生态系统。

8 核心观点提炼

  1. 不要构建 Agent，构建 Skills。 通用 Agent + 领域 Skills 的组合优于为每个场景构建独立的 Agent 系统。
  2. 渐进式披露是技能架构的根基。 它使数百个 Skills 可以共存于同一个 Agent 系统中而不会耗尽上下文窗口。
  3. Skills 让知识可复用、可共享、可版本管理。 团队可以将领域知识编码为 Skills，像管理代码一样管理知识。
  4. Skills 补全了 MCP 的定位。 MCP 解决的是"工具接入"问题，Skills 解决的是"流程知识"问题。两者结合，Agent 既知道用什么工具，也知道怎么用。
  5. 开放标准是生态繁荣的基础。 agentskills.io 标准确保了 Skills 可以在不同平台的 Agent 之间移植。
  6. Agent 自主创建 Skills 是终极形态。 当 Agent 能自己写、自己优化自己的 Skills 时，人与 AI 的协作将进入新阶段。

9 评价与启示

这篇文章为什么重要？

Agent Skills 的提出回应了当前 AI Agent 领域的一个根本矛盾：一方面，通用大语言模型的推理能力在飞速提升；另一方面，在实际业务中部署 Agent 时，真正决定成败的往往是领域知识和操作流程的覆盖度。Skills 提供了一种系统化的知识封装方案，将"Agent 知道什么"从 Agent 本身解耦出来。

对我个人的启示

  • 从"提示词工程"到"技能工程"：Skills 将提示词工程提升为软件工程实践——有结构、有版本、有测试、有生命周期管理。
  • 知识复用的标准化方案：团队积累的领域知识不再散落在文档或个人提示词中，而是以标准化 Skills 形式被系统化管理和复用。
  • 与我的项目关联：在 AI-learning 项目中，可以将学习路线、框架使用指南、调试流程等封装为 Skills，让学习过程本身也能得到 Agent 的辅助。
  • 开放生态带来的机遇：agentskills.io 标准意味着 Skills 社区可能像 npm/GitHub 一样繁荣，会出现大量可复用的高质量 Skills。
