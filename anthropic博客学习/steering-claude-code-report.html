🎯 操控 Claude Code：七种自定义方式

来源：Anthropic 官方博客  |  日期：2026-06-18  |  报告生成：2026-06-23

📋 概述

Anthropic 于 2026 年 6 月 18 日发布官方博文 "Steering Claude Code: skills, hooks, subagents and more"， 系统性地阐述了操控 Claude Code 行为的七种核心机制。 这篇文章本质上是一份「如何让 AI 编码助手听话」的操作手册—— 从项目级的 CLAUDE.md 到生命周期钩子 Hooks，构成了一套完整的分层指令体系。

核心思想：渐进式信息披露（Progressive Disclosure）
不是把所有指令塞进一个文件，而是按场景触发、按需加载，避免上下文膨胀和 token 浪费。

🧭 决策框架

面对七种机制，选哪个？ 官方提供了以下判断流程：

方法 位置 加载时机 Token 成本 核心用途
CLAUDE.md 项目根 / 子目录 会话启动 中 项目背景、编码规范、构建命令
Rules .claude/rules/*.md 会话启动 / 路径匹配 低~中 路径/文件类型相关的条件规则
Skills .claude/skills/*/SKILL.md 描述启动时加载，正文触发时加载 低 按需调用的工作流程（部署、审查、发布）
Subagents .claude/agents/*.md 被委派时加载 隔离(各自独立窗口) 需要独立上下文的复杂并行任务
Hooks settings.json 生命周期事件 极低(仅触发) 格式化、阻止危险操作、通知
Output Styles .claude/output-styles/*.md 会话启动 高(替换系统提示) 改变 Claude 的交流风格/角色
Append System Prompt CLI --append-system-prompt 单次调用 低 临时追加指令，覆盖默认行为

① CLAUDE.md — 项目级背景文件

📄

是什么

项目根目录或子目录下的 Markdown 文件，内容在每次会话启动时自动注入为上下文。用户级全局文件位于 ~/.claude/CLAUDE.md。

🎯

适合放什么

  • 构建命令和测试命令
  • 目录结构说明
  • 编码规范和团队约定
  • 项目架构概述
⚠️ 关键建议：保持在 200 行以内。
过大的 CLAUDE.md 会导致上下文膨胀。事实性信息留在这里，过程性工作流迁移到 Skills。

加载机制

级别位置加载时机
用户全局~/.claude/CLAUDE.md所有项目，会话启动
项目根<project>/CLAUDE.md会话启动
子目录<project>/subdir/CLAUDE.md当 Claude 工作在该目录时按需加载

② Rules — 路径作用域规则

Rules 是 CLAUDE.md 的模块化替代方案。 通过 YAML frontmatter 中的 paths: 字段实现条件加载—— 只有当 Claude 操作的文件匹配 glob 模式时，对应规则才会注入上下文。

YAML .claude/rules/api-endpoints.md 
---
paths:
  - "src/api/**/*.ts"
  - "src/routes/**/*.ts"
---

# API 端点开发规则

- 所有端点必须使用 Zod 进行输入验证
- 错误响应统一使用 `createErrorResponse()` 工具函数
- 每个端点必须有对应的 OpenAPI 注释
💡 优势：约 40% 的 token 节省—— 只加载当前文件类型相关的规则，而非整个 CLAUDE.md。 无 paths: 字段的规则文件始终加载（等同 CLAUDE.md）。

Glob 模式示例

模式匹配范围
src/api/**/*.tssrc/api/ 下所有 .ts 文件（递归）
**/*.test.ts项目中所有测试文件
src/components/*.tsxsrc/components/ 直接子级（不递归）
**/*.{ts,tsx}所有 TypeScript/TSX 文件
**/*.vue所有 Vue 组件

③ Skills — 过程化工作流

Skills 是 Claude Code 的核心扩展机制。 每个 Skill 是一个独立文件夹，内含 SKILL.md（必选）以及可选的 workflows/、references/、templates/、scripts/ 子目录。

SKILL.md 最小结构

Markdown.claude/skills/deploy/SKILL.md
---
name: deploy
description: "Deploy to production. Use when: deploy, release, ship, publish"
disable-model-invocation: true  # 仅手动调用
---

<objective>将当前分支部署到生产环境</objective>

<process>
1. 确认当前分支已通过所有 CI 检查
2. 运行 `npm run build` 确认构建成功
3. 执行 `git push origin HEAD:production`
4. 等待部署 Webhook 返回 200
</process>

<success_criteria>生产环境健康检查返回 200</success_criteria>

关键 Frontmatter 字段

字段说明
nameSkill 名称，同时也是斜杠命令名（/deploy）
description关键！ 用于自动发现——Claude 根据描述判断何时调用
disable-model-invocationtrue = 只能手动调用。适合部署、提交等有副作用操作
context: fork在隔离子代理中运行，不污染主对话上下文
model指定此 Skill 使用的模型（sonnet / opus / haiku）
allowed-tools无需权限确认即可使用的工具列表
user-invocablefalse = 仅供 Claude 内部自动调用

调用方式

  • 斜杠命令：/deploy → 直接调用
  • 自动触发：Claude 加载 description 列表，当用户请求匹配时自动调用
  • 带参数：/deploy staging → 使用 $ARGUMENTS 或 $1 接收
  • @-mention：@deploy 确保调用特定 Skill
💡 最佳实践：保持 SKILL.md 在 500 行以内。将详细步骤移到 workflows/， 将领域知识移到 references/。使用 Router 模式（SKILL.md 作为入口，路由到具体工作流）。

④ Subagents — 隔离上下文代理

Subagents 是拥有独立 200K-token 上下文窗口的专用 AI 实例。 它们在自己的沙盒中工作——中间的工具输出、堆栈追踪、grep 结果、错误的尝试都留在子代理内部， 只有最终结果返回给主会话。

子代理定义文件

Markdown.claude/agents/code-reviewer.md
---
name: code-reviewer
description: "Review code for bugs, security issues, and style."
tools: Read, Grep, Glob, Bash
model: opus
---

你是一个高级代码审查员。审查代码时检查：

## 安全检查
- SQL 注入、XSS、路径遍历
- 权限验证和输入校验

## 质量检查
- 边界情况和错误处理
- 性能和资源释放

## 输出格式
返回结构化 JSON：{ "issues": [...], "score": 0-10 }

核心特性

特性说明
上下文隔离每个子代理拥有独立的 200K 上下文窗口，中间过程不污染主会话
最小权限通过 tools 字段显式授予工具，不给多余权限
模型选择按任务选择：Haiku(机械任务) / Sonnet(日常工作) / Opus(深度推理)
后台运行background: true 使子代理异步执行
Worktree 隔离isolation: worktree 创建独立 git 工作树副本
嵌套限制子代理不能再次生成子代理（一级深度），但支持最多 5 层动态工作流嵌套

调用方式

  • 自动委派：Claude 根据 description 字段自动匹配任务
  • 自然语言："用 code-reviewer 子代理审查这个 PR"
  • @-mention：@agent-code-reviewer 强制调用
  • 会话级：claude --agent code-reviewer 整会话使用子代理配置
📐 设计原则：一个子代理只做一件事。 不要创建"万能"子代理。使用描述字段引导自动委派—— "Use proactively after writing new code to check for common issues"。

⑤ Hooks — 确定性生命周期触发器

Hooks 是系统强制执行的确定性机制—— 不依赖 AI 记忆，在指定生命周期事件发生时自动触发 shell 命令、HTTP 请求或 MCP 工具。

八种事件类型

事件触发时机典型用途
PreToolUse工具执行前拦截危险操作（exit 2 = 阻止）
PostToolUse工具执行成功后自动格式化、运行测试、日志记录
PostToolUseFailure工具执行失败后错误日志记录、通知
PermissionRequest请求用户授权时自定义授权逻辑
SessionStart会话开始/恢复时加载环境配置、连接检查
PreCompact上下文压缩前保留关键信息
StopClaude 完成响应后清理、通知、验证
UserPromptSubmit用户提交提示词时输入验证、上下文注入

配置示例

JSON.claude/settings.json
{
  "hooks": {
    // 1. 代码修改后自动格式化
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [{
          "type": "command",
          "command": "npx prettier --write \"$CLAUDE_TOOL_INPUT_FILE_PATH\""
        }]
      }
    ],
    // 2. 阻止危险命令
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{
          "type": "command",
          "command": "if echo \"$CLAUDE_TOOL_INPUT\" | grep -qE 'rm -rf /|DROP DATABASE|format c:'; then echo 'Blocked!' >&2; exit 2; fi"
        }]
      }
    ],
    // 3. 保护敏感文件
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{
          "type": "command",
          "command": "python3 -c \"import json,sys;d=json.load(sys.stdin);sys.exit(2 if any(p in d.get('tool_input',{}).get('file_path','') for p in ['.env','package-lock.json','.git/','secrets']) else 0)\""
        }]
      }
    ]
  }
}

五种操作类型

类型说明
command执行 shell 命令。exit code 2 阻止操作
http发送 HTTP 请求，可用于触发 Webhook
mcp_tool调用 MCP 服务器的工具
prompt向 Claude 注入提示词
agent启动子代理处理事件
⚠️ 安全关键：exit code 2 = 阻止操作。 任何其他非零退出码只记录错误但不阻止。 PostToolUse 无法撤销已执行的操作——需在 PreToolUse 中拦截。 输出上限 10,000 字符。多 Hook 冲突时，最严格的决策胜出（deny > defer > ask > allow）。

⑥ Output Styles — 输出风格 / 系统提示替换

Output Styles 替换 Claude 的系统提示词——这是七种方法中指令权重最高的机制。 它改变 Claude 的交流方式（语气、格式、详细程度），但不改变能力（工具仍然可用）。

内置风格

风格行为适用场景
Default标准软件工程助手，简洁、任务导向有经验的开发者
Explanatory在编码任务间添加教育性解释，说明选择理由学习代码库的新成员
Learning协作式边做边学，使用 TODO(human) 标记初学者

自定义风格

Markdown.claude/output-styles/academic.md
---
name: Academic
description: "Formal academic writing style"
keep-coding-instructions: false
---

# 风格指令
以学术论文风格回应。使用第三人称，避免口语化。
每个观点需提供引用或逻辑推导。

keep-coding-instructions 关键设置

值效果
false (默认)移除所有软件工程指导（测试、代码质量检查等）。工具仍然可用，但不再主动做 SE 检查
true保留所有编码指令，风格内容追加在完整默认提示之上。适合只需调整语气的编码场景
📐 优先级最高：Output Styles 指令的遵循权重高于 CLAUDE.md 和任何其他机制。 切换方式：/output-style Explanatory 或通过 /config 交互选择。 更改效果在下一次会话开始时生效。

⑦ Append System Prompt — 单次调用追加指令

--append-system-prompt 是 CLI 级别的追加机制—— 追加式（不替换），仅对单次调用生效。 最适合轻量级临时指令。

Shell--append-system-prompt 用法
# 单次调用时要求更详细的输出
claude --append-system-prompt "Be extra thorough today. Explain every step."

# 切换写作风格
claude --append-system-prompt "Write all responses in Traditional Chinese."

# 扮演特定角色
claude --append-system-prompt "You are a security auditor. Review code for OWASP Top 10."
💡 适用场景：一次性任务需要的临时指令，不值得写入 CLAUDE.md 或创建 Skill。 与 Output Styles 不同，它是追加而非替换——不会移除原有的软件工程指导。

指令优先级总排序

从高到低：
用户显式指令 → Hooks (PreToolUse 拦截) → Output Styles → Subagents (系统提示) → Skills → Append System Prompt → CLAUDE.md ≈ Rules

🔑 总结 & 核心原则

🧩 瘦身 CLAUDE.md

事实留在 CLAUDE.md，过程迁移到 Skills，文件类型相关规则迁移到 Rules。目标是每个会话只加载真正需要的上下文。

🔒 安全用 Hooks

PreToolUse 做拦截（exit 2），PostToolUse 做自动化（格式化、测试）。Hooks 是唯一不依赖 AI 记忆的确定性机制。

🏝️ 隔离用 Subagents

复杂搜索、多文件分析、批量操作——用子代理处理。主会话只看到结果，上下文不膨胀。一个子代理只做一类任务。

📦 流程用 Skills

部署、代码审查、发布检查清单等重复性过程工作流，封装为 Skills。有副作用的操作设置 disable-model-invocation: true。

⚠️ 反模式提醒：不要把所有东西都塞进 CLAUDE.md。
这是官方博文最核心的建议。一个 500+ 行的 CLAUDE.md 导致： 上下文膨胀 → 响应变慢 → AI 注意力稀释 → 指令遵循度下降。 应该根据"何时需要"来分配内容到不同机制中。
