Claude Cowork 入门最佳实践
—— 从聊天到委托，让 AI 产出交付物

原文：Best practices for getting started with Claude Cowork · 作者：Austin Lau（Anthropic 增长营销负责人） · 2026年6月

一、概述与作者背景

本文作者 Austin Lau 是 Anthropic 的增长营销负责人，非技术背景、不会写代码。 他在没有工程团队支持的情况下，独自一人扛起了 Anthropic 长达 10 个月的全部增长营销工作—— 核心秘诀就是 Claude Cowork。他将多达 90% 的日常任务委托给 Claude，自己只做决策和判断。

"关键的心态转变：从把 Claude 当作聊天工具，到把它当作一个可以产出交付物的同事。" —— Austin Lau

二、Chat / Cowork / Code 三角色定位

Anthropic 将 Claude 产品线划分为三个清晰的角色，各自对应不同场景：

产品适用场景核心能力典型用户
Chat 头脑风暴、快速问答、压力测试想法、定位问题、随机提问 对话式交互、单轮或多轮问答、知识检索 所有人
Cowork 产出交付物：文档、PPT、电子表格、报告、分析 多步骤执行、文件读写、连接器（Gmail/Slack/Notion等）、定时任务、子智能体 非技术知识工作者
Code 软件开发、代码编写与调试、工程任务 终端操作、代码编辑、Git 集成、测试运行 开发者
"Chat 给你想法，Cowork 给你交付物，Code 给你软件。"

三、判断 "Cowork 型任务" 的五个标准

Austin 提出了判断一个任务是否适合交给 Cowork 的 五个标准——不需要全部满足，但好候选通常匹配其中多项：

▲ 五个标准环绕式视图 —— 中心是 Cowork 型任务，外围是五大判断维度

#标准说明为什么重要
① 多输入源 任务涉及多个文件、整个文件夹，或文件 + 连接器（Slack/Gmail 等）的组合 Cowork 的价值在于跨来源整合——单一来源的问题用 Chat 就够了
② 产出文件 交付物是可以附上、展示、分享或复用的东西（文档、PPT、表格、CSV） 文件输出意味着任务有明确的"完成"标准，你可以直接审阅结果
③ 可复现 一次性任务也可以，但每日/每周重复执行的任务是最佳场景 你可以用定时任务（scheduled tasks）自动化——设一次，永久运行
④ 你知好坏 你能在 15 秒内判断结果——正确、错误，或完成了 70% 快速反馈循环是迭代改进的基础；如果你自己都不知道什么算"好"，AI 更不可能知道
⑤ 中间过程枯燥 思考发生在开头（决定你要什么）和结尾（判断结果）。中间繁琐的提取、编译、核对、格式化——这些就是你要委托出去的 这是 Cowork 的核心价值主张：你做判断，AI 做执行

四、你的前 10 分钟：从零到第一个交付物

  1. 打开桌面应用，切换到 Cowork 标签页

    无需终端、无需代码。Claude Desktop 是 Cowork 的原生界面。

  2. 给 Claude 一些可用的素材

    拖入文件、指向一个文件夹，或连接应用（Slack、Gmail、Notion、CRM 等）。空手而来很难产出好东西。

  3. 告诉 Claude 你想要的产出结果

    描述交付物并提供上下文——你要的不是"帮我分析数据"，而是"帮我生成一份包含趋势图和关键发现的周报"。

  4. 从一个你熟悉的任务开始

    不要拿陌生任务练习——选一个你非常了解的任务，这样你能立刻看出 Cowork 的优势和不足。

  5. ⭐ 让 Claude 在动手前先问你问题

    这是 Austin 称之为"最有用的习惯"：在 Prompt 中加入——"在开始之前，先复述我的需求确保我们一致，然后提出你所有的澄清性问题。"回答 5 个问题花 30 秒，事后修补同样的漏洞花的是时间和 Token。

"回答五个前置问题花你 30 秒。事后发现同样的漏洞，花的是你的时间和 Token，而且修正起来很痛苦。" —— Austin Lau

八、核心启示

  1. 心态转变是第一步——从"跟 Claude 聊天"到"把 Claude 当同事委托任务"。聊天的产出是想法，委托的产出是交付物
  2. 选对任务事半功倍——用五个标准筛选：多输入、文件输出、可复现、你知好坏、中间枯燥。不满足大部分标准的任务，用 Chat 可能更合适
  3. 前置澄清 30 秒 > 事后修补 30 分钟——每次 Prompt 都让 Claude 先复述需求并提问，这是"最有用的习惯"
  4. 非技术背景反而是优势场景——Austin 不会写代码，但他比大多数工程师更高效地使用了 Claude。Cowork 的设计目标用户就是他这样的人
  5. 基础设施决定天花板——about-me.md、全局说明、文件夹结构、连接器——这些一次性的设置投入，决定了后续每次交互的质量上限
  6. 从个人到团队的扩展路径清晰——五级成熟度模型提供了从 Level 1（随意使用）到 Level 5（企业规模化）的可操作路线图
  7. 连接器 > 浏览器 > 屏幕操作——给 Claude 最精确的工具接口，优先级递减，结构化数据优于非结构化抓取
