文章背景与核心观点

Overview

2025 年 9 月 29 日，Anthropic 在 Claude Code 2.0 发布的同时，正式将 Claude Code SDK 更名为 Claude Agent SDK，并发表了这篇由多位工程师联合撰写的技术博客。文章的核心论点非常明确：

💡
核心命题：给模型一台真正的计算机（文件系统、终端、浏览器），比在 Chat API 之上重新发明工具调用，是通往通用 Agent 更短、更可靠的路径。

核心理念：Agent 的本质是一个感知-行动循环（Perception-Action Loop）——收集上下文 → 执行行动 → 验证结果 → 重复。

团队发现，开发者使用 SDK 的场景远超代码本身——深度研究、视频创作、客户支持、法律分析、知识库管理、金融分析——因此决定将其从"编码工具"升级为"通用 Agent 框架"。文章详细阐述了构建 Agent 的三个核心环节以及 SDK 如何支撑这每一环节。

核心架构：Agent Loop

Architecture

Agent 的核心是一个持续运行的感知-行动循环。模型每一次迭代都会执行四个步骤，形成一个闭环：

🔍 收集上下文 Gather Context
→
⚡ 执行行动 Take Action
→
✅ 验证工作 Verify Work
→
🔄 重复 Repeat
Agent Loop
📌

关键洞察：Agent Loop 并不要求每一步都完美——它通过快速迭代来逼近正确结果。核心优势在于 反馈闭环：行动产生可观察的结果，结果指导下一步行动。这使得 Agent 能够自主纠错，无需人工介入每一次失误。

🔍

第一步：收集上下文

Gather Context

有效的上下文收集是 Agent 成功的基石。文章详细阐述了四种上下文收集机制：

📂 文件系统 / Agentic Search

Agent 可以自主决定需要查看哪些文件、读取哪些目录，并通过 Glob/Grep 工具进行搜索。它不只是被动接收信息，而是主动探索代码库或文档集。

🔍 语义搜索

借助向量搜索和自然语言查询，Agent 能够基于语义而非关键词查找相关信息。这使得 Agent 可以在大型代码库或文档库中快速定位相关内容。

🧩 Subagents

将复杂任务拆分为多个子任务，分配给独立的 Subagent 并行执行。每个 Subagent 拥有独立的上下文窗口，避免上下文污染，天然支持并行加速。

📦 Compaction

当上下文窗口接近上限时，Agent 会自动对历史对话进行智能压缩和摘要，保留关键信息的同时释放空间。这使 Agent 能够执行超长周期的复杂任务。

🧩 Subagents 详解

Subagent 是 Agent Loop 中的一个强大抽象。其核心设计理念：

  • 隔离性：每个 Subagent 拥有独立的上下文窗口，不会因一个子任务的上下文污染主 Agent
  • 并行性：多个 Subagent 可同时运行，显著加速多步骤调研或多文件修改
  • 专注性：每个 Subagent 只聚焦一个具体子任务，prompt 更短、更精确，减少幻觉
  • 结果聚合：主 Agent 收集各 Subagent 的输出，进行分析、对比和综合

📦 Compaction 机制

Claude Agent SDK 的 Compaction 解决了 Agent 长期运行的上下文溢出问题：

  • 自动触发：当上下文接近限制时自动启动，无需人工干预
  • 智能摘要：对历史消息进行结构化摘要，保留关键决策、已尝试方案和结果
  • 无损恢复：压缩后 Agent 仍能通过摘要了解前文，维持行为一致性
  • 这使得 SDK 可以支撑数小时甚至数天的自主运行
⚡

第二步：执行行动

Take Action

Agent 通过丰富的工具集与环境交互，执行具体的操作。SDK 提供了多种内置工具和扩展机制：

工具用途说明
Read读取文件支持文本、图片（PNG/JPG）、PDF、Jupyter Notebook
Write创建文件写入新文件到磁盘
Edit修改文件精确的搜索替换编辑，避免整文件重写
Bash执行命令运行终端命令、脚本、编译、测试等
Glob文件搜索按通配符模式查找文件
Grep内容搜索按正则表达式搜索文件内容
WebSearch网络搜索获取最新网络信息
WebFetch页面抓取获取并解析网页内容
Task子任务启动 Subagent 并行执行子任务

🔗 MCP (Model Context Protocol) 集成

MCP 是 Anthropic 推出的开放协议，允许 Agent 通过标准化接口接入任意外部系统和数据源：

  • 三种连接方式：In-process SDK Server、外部子进程 stdio Server、远程 HTTP Server
  • 自定义工具装饰器：使用 @tool 装饰器定义函数，通过 create_sdk_mcp_server 暴露给 Agent
  • 生态丰富：支持 Puppeteer（浏览器自动化）、数据库连接器、API 网关、文件系统等
  • 命名规范：工具命名模式为 mcp__{server_name}__{tool_name}，避免命名冲突

⚡ 批量并行执行

Agent 具备同时发起多个行动的能力：

  • 同时读取多个文件以加速理解上下文
  • 并行执行多个 Bash 命令（如同时安装依赖和启动服务）
  • 同时对多个文件进行编辑修改
  • 批量发送网络请求进行数据采集
  • 不过 Agent 会谨慎平衡并行度，避免资源过载
✅

第三步：验证工作

Verify Work

验证环节是 Agent 自主纠错的关键。文章提出了三个层面的验证策略：

📋 规则验证

通过预定义规则约束 Agent 行为，例如"禁止修改 package-lock.json"、"生产环境的变更必须经过测试"。规则可作为系统提示的一部分或通过 Hook 机制执行。

📸 视觉反馈

对于 UI/前端任务，Agent 可以主动截图查看渲染效果，通过视觉反馈判断按钮位置、颜色、布局是否符合预期。这对于传统文本日志难以捕获的问题尤为有效。

⚖️ LLM-as-Judge

Agent 自我审视自己的输出，评估是否正确、完整、符合要求。也可以使用另一个更严格的模型（或同一模型以更严格的 prompt）对结果进行评判。

🔄

验证闭环：当验证失败时，Agent 不会简单地放弃——它会基于失败信息重新收集上下文（例如读取错误日志），调整策略后再次尝试。这个"验证 → 重试"循环是 Agent 从错误中恢复的核心机制。

SDK 安装与快速开始

Setup
Bash 
pip install claude-agent-sdk                      # 安装 Python SDK（要求 Python 3.10+）
npm install @anthropic-ai/claude-agent-sdk         # 安装 JS/TS SDK
export ANTHROPIC_API_KEY=sk-ant-...                # 环境变量认证，SDK 通过此密钥调用 Claude API
Python 
import anyio                                             # 引入 anyio 异步运行时库
from claude_agent_sdk import query, ClaudeAgentOptions    # 导入 SDK 核心：query 执行函数 + 配置类

async def main():                                     # 定义异步主函数
    options = ClaudeAgentOptions(                       # 创建 Agent 配置实例
        system_prompt="你是一个有帮助的助手",            # 系统提示词，定义 Agent 的角色和行为准则
        max_turns=1,                                  # 最大交互轮次，1=单轮对话，不执行工具调用
    )
    async for message in query(                         # 发起 Agent 请求，以异步流式方式接收消息
        prompt="Hello, who are you?",                  # 用户输入，作为 Agent 的起始指令
        options=options,                                # 传入之前配置的参数
    ):
        print(message)                                  # 逐条打印 Agent 返回的响应内容

anyio.run(main())                                       # 用 anyio 事件循环启动异步主函数
Python 
import asyncio                                          # 引入 asyncio 异步运行时库

asyncio.run(main())                                       # 用 asyncio 事件循环启动主函数

代码示例解析

Examples

示例 1：自定义 MCP 工具

通过 @tool 装饰器定义天气查询工具，注册到 MCP Server 后供 Agent 调用：

Python 
from typing import Any                                       # 导入类型注解 Any，用于泛型参数
import httpx                                               # 导入 httpx 异步 HTTP 客户端库
from claude_agent_sdk import tool, create_sdk_mcp_server, \  # ─┐
    query, ClaudeAgentOptions                               # ─┘ 导入 SDK：tool 装饰器、MCP 创建、query 执行、配置类

# ========== 第一步：用 @tool 装饰器定义工具函数 ==========
@tool(                                                      # @tool 装饰器将函数暴露为 MCP 工具
    "get_temperature",                                      # 工具名称，Agent 通过此名调用
    "获取指定位置的当前温度",                                # 工具描述，帮助 Agent 理解用途
    {"latitude": float, "longitude": float},               # 参数 schema：经纬度均为浮点数
)
async def get_temperature(args: dict[str, Any]) -> dict[str, Any]:  # 异步工具函数，接收参数字典，返回内容字典
    async with httpx.AsyncClient() as client:                 # 创建异步 HTTP 客户端（自动管理连接池）
        response = await client.get(                          # 发起异步 GET 请求
            "https://api.open-meteo.com/v1/forecast",        # Open-Meteo 免费天气 API
            params={                                           # 查询参数
                "latitude": args["latitude"],                   # 纬度（由 Agent 传入）
                "longitude": args["longitude"],                 # 经度（由 Agent 传入）
                "current": "temperature_2m",                   # 请求当前地表温度数据
                "temperature_unit": "celsius",               # 温度单位：摄氏度
            },
        )
        data = response.json()                               # 将 API 响应解析为 JSON
    return {                                                 # 返回 MCP 标准格式的结果字典
        "content": [                                         # content 是 MCP 协议的内容数组
            {"type": "text",                                   # 内容类型：纯文本
             "text": f"温度: {data['current']['temperature_2m']}°C"}  # 从响应中提取温度值
        ]
    }

# ========== 第二步：注册到 in-process MCP Server ==========
weather_server = create_sdk_mcp_server(                    # 创建进程内 MCP Server 实例
    name="weather",                                          # Server 名称，Agent 配置时引用
    version="1.0.0",                                         # Server 版本号
    tools=[get_temperature],                                  # 注册上一步定义的工具函数
)

# ========== 第三步：在 Agent 配置中启用该 MCP Server ==========
async def main():                                           # 定义异步主函数
    options = ClaudeAgentOptions(                             # 创建 Agent 配置
        mcp_servers={"weather": weather_server},            # 注册 MCP Server，key 为自定义名称
        allowed_tools=["mcp__weather__get_temperature"],   # 授权工具：mcp__{server}__{tool} 格式
    )
    async for message in query(                               # 发起异步 Agent 请求
        prompt="旧金山的温度是多少？",                        # Agent 会自动提取经纬度并调用天气工具
        options=options,                                      # 传入配置
    ):
        print(message)                                        # 输出 Agent 响应

options = ClaudeAgentOptions(                                  # 创建 Agent 配置实例
    mcp_servers={                                               # 注册多个 MCP Server，支持三种连接方式

        }
    }
)

可构建的 Agent 类型

Use Cases

文章展示了 Claude Agent SDK 的通用性，列举了多种实际应用场景：

💰 金融分析 Agent

自动拉取股票数据、分析财务报表、评估投资组合风险，生成投资建议报告。支持对接 Bloomberg Terminal 等金融数据源。

🧑‍💼 个人助理 Agent

管理日历、预订旅行、处理邮件、安排会议。能够执行多步骤工作流，如"帮我订下周二飞往纽约的航班并安排酒店"。

🎧 客户支持 Agent

处理含混的客户请求，在必要时升级到人工。可访问知识库、订单系统、退货流程等后端系统。

🔬 深度研究 Agent

分析大量文档集合，执行多角度调研，综合不同来源的信息，生成结构化研究报告。利用 Subagent 并行探索不同方向。

🎬 视频创作 Agent

编写视频脚本、生成素材、调用编辑工具处理视频文件，自动完成从创意到成片的工作流。

⚖️ 法律分析 Agent

检索法律条文、判例库，进行法律风险分析，辅助合同审查，生成法律备忘录。

最佳实践

Best Practices

🎯 专业化：一个 Agent 只做一件事

每个 Agent 应该专注于一个特定领域，配备最小必要工具集。例如"前端测试 Agent"只需要浏览器工具和文件读写，不需要 Bash 访问。专业化 Agent 比通用 Agent 更可靠、更安全。

🔒 最小权限原则

allowed_tools 只赋予 Agent 完成任务所必需的最少工具。对于敏感操作（如文件删除、数据库写入），通过 Hook 机制（PreToolUse）增加额外的安全审批层。

📝 规则即护城河

通过 system prompt 或 hook 定义行为边界，例如："永远不要直接修改生产数据库"、"修改 API 前必须先更新文档"。规则应具体、可执行，避免模糊表述。

👁️ 可观测性

Agent 的决策过程应该可追踪。集成日志记录、步骤回放、token 用量监控。SDK 支持与 MLflow 等工具集成，实现自动 tracing。

🔄 测试优先开发

先为 Agent 编写测试用例，再开发功能。Agent 在完成任务后应能自动运行测试验证结果，形成"编码 → 测试 → 修复"的闭环。

🔧 善用 Hook 机制

Hook 提供了在工具调用前后注入自定义逻辑的能力。例如 PreToolUse Hook 可以拦截所有 Bash 命令，检查是否包含危险操作（如 rm -rf），PostToolUse Hook 可记录所有工具调用的执行结果。

🎯

总结与展望

Summary
🔑

全文核心思想：构建 Agent 的最短路径，不是从头实现工具调用、状态管理、上下文窗口等基础设施，而是直接给模型一台计算机（通过 SDK），然后通过精心设计的 Agent Loop（收集上下文 → 执行行动 → 验证工作）来引导它完成任务。

🚀 SDK 的核心优势

基于成熟的 Claude Code CLI，继承了文件操作、代码生成、Bash 执行、MCP 集成等能力，无需从零构建 Agent 基础设施。

🧩 扩展性

通过 MCP 协议接入任意外部系统，自定义工具、数据源、服务。生态正在快速增长，社区贡献了大量 MCP Server。

🛡️ 安全机制

多层次的权限控制（工具级别、操作级别）、Sandbox 隔离、Hook 注入安全检查，支持生产环境的安全部署。

📈 未来方向

更完善的 Subagent 管理、更细粒度的权限控制、更丰富的内置 MCP Server、以及与 Claude Code CLI 更深度的协同。

💡
