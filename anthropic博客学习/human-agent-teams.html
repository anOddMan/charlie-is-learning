Building Effective Human-Agent Teams

📅 2026-06-24 ✍️ Kristen Swanson（Anthropic Education 团队） ⏱️ 5 分钟阅读
📎 原文：claude.com/blog/building-effective-human-agent-teams

📋 文章背景

这是 Anthropic 官方博客于 2026 年 6 月 24 日 发布的文章，作者为教育团队的 Kristen Swanson。文章总结了 Anthropic 内部对人机团队协作的实践经验，核心论点是：

高效的 AI 协作不是"用不用 Agent"的问题，而是"团队是否刻意实践了人机协作的基本功"的问题。基本功扎实的团队，Agent 放大效能；基本功缺失的团队，Agent 放大混乱。

文章发表前一天（6 月 23 日），Anthropic 正式发布了 Claude Tag——一个嵌入 Slack 的 AI Agent 功能，使团队可以 @Claude 像同事一样调用 AI，并配备独立身份、权限体系和审计日志。

65%Anthropic 产品团队代码由内部版 Claude Tag 生成 500Agent 独立修复的 Bug 数量

🎯 核心概念：Multiplayer Agents（多人 Agent）

文章提出了一个关键范式转变：从 "单玩家模式"（一个人类 + 一个 Agent 私密协作）到 "多玩家模式"（多个 Agent 与多个人类在同一工作空间中同时协作）。

维度单玩家（Single-player）多玩家（Multiplayer）
身份Agent 借用人类身份Agent 拥有独立身份和凭证
工作空间私密 1:1 对话共享频道（Slack / 文档 / 代码库）
信息可见性仅对话双方可见默认公开，全团队可检索
上下文来源人类主动提供Agent 自动从公共频道、文档、代码中摄取
权限模型继承人类权限Agent 级 scope（按频道/仓库授权）

Lesson 1：在公开中工作，给 Agent 充足的上下文

核心理念

Agent 的信息获取能力远超人类（能快速阅读海量文本），但前提是信息必须可被检索。如果决策发生在私聊、口头沟通或未记录的会议中，Agent 就是"盲人"。

实践要点

🔓
工作空间级安全边界，而非逐条审批

使用清晰的工作空间级安全边界替代逐项资源共享审批。Agent 需要的不是每条信息的访问授权，而是整个工作空间的可读权限。

📢
默认公开的沟通文化

决策在频道、文档、会议记录中沉淀为可检索文本。Slack 消息、代码评审、设计文档、会议纪要——这些是 Agent 的"眼睛"。

📚
异步协作优于实时同步

Agent 不受时区限制，可以异步消化上下文。团队应优先用文档而非实时会议传递决策信息，让 Agent 能"追得上"。

"Agent 只能基于它能看到的资料工作。如果一个决策没有被写下来，它就不存在——至少对 Agent 来说不存在。"

Lesson 2：每个成员（人或 Agent）都有明确角色和工具

核心理念

人机团队共享一份花名册、一套制品、一个工作空间。Agent 有清晰的角色定义、专用的 Skill 文件、独立的访问凭证和工具链。

Agent 角色类型（Roster）

角色职责所需工具
数据分析 Agent查询数据、生成报表、识别趋势BigQuery、SQL、数据可视化
设计规范 Agent检查 UI 实现是否符合设计系统Figma API、CSS 分析工具
研究综合 Agent整合多源信息、发现知识缺口文档搜索、Web 检索
QA 测试 Agent自动化端到端测试、回归检查Playwright MCP、CI/CD 集成
发布管理 Agent管理发版流程、变更日志、部署检查GitHub API、部署系统
沟通调度 Agent批量聚合问题、控制人类注意力消耗Slack API、任务管理系统

关键机制：Agent 可派生子 Agent

一个 Agent 可以"spawn"（孵化）其他 Agent，将子任务委派给拥有正确记忆和访问权限的专用 Agent。这构成了 Agent 到 Agent 的委托链，使团队能自动拆解复杂任务。

Lesson 3：设定北极星，让 Agent 更主动

核心理念

Agent 不应该只是"等待指令"的执行者。当 Agent 拥有丰富的上下文 + 明确的角色 + 一个北极星目标时，它们会主动提议新项目和新的工作流。

北极星三要素

1

由人类设定

北极星始终由人类定义，根植于业务使命。Agent 可以建议，但无权修改北极星。

2

宏大且具体

足够宽泛以激发主动性（"让产品入职过程更有帮助"），足够具体以提供方向。

3

显式授权

人类明确选择哪些 Agent 有权主动提议新工作。不是所有 Agent 都需要这个权限。

实际案例

内部工具团队设定了北极星："让产品入职过程更有帮助"。团队中的一个 Agent 主动建议了文案修订方案，这些修订可度量地提高了入职成功率。

Lesson 4：渐进式建立信任

核心理念

授予 Agent 的自主权应与其展示的可靠性成正比。就像信任一个新同事一样——从小任务开始，逐步扩大范围，过程中持续反馈。

信任建设四阶段

阶段人类参与度Agent 自主范围验证机制
1. 全面审核每项决策都审核仅限低风险任务人工逐一检查
2. 引入验证者抽查 + Agent 互查中等复杂度任务Doer-Verifier 模式
3. 建立信任记录关注例外情况大部分常规任务周报复盘 + 自动化检查
4. 条件自主仅参与战略决策复杂任务 + 主动提议多层 Agent 交叉验证

人类注意力是稀缺资源

一旦 Agent 进入独立运行阶段，团队刻意训练它们将人类注意力视为稀缺资源：

📦
批量聚合问题

不逐条 ping 人类，而是积累成摘要后一次性提审。

🔄
重复关键上下文

每次提审时附上必要的背景信息，让人类能快速进入状态。

📏
限制每次审查量

控制每次提交人类审查的事项数量，避免审查疲劳。

🤖
专门的调度 Agent

部分团队创建了专门角色，其唯一职责就是决定如何批量汇总并仅提升最重要的沟通给人类。

Doer-Verifier 模式

"一个 Agent 执行任务，另一个 Agent 检查它的工作。"——团队花费正确性验证的时间，而不是从零开始完成任务的时间。

🏭 工程团队案例：500 个 Bug 独立修复之路

背景

一位工程负责人接手了一个新团队，面对庞大的积压 Backlog。他邀请了几个人类成员和几个 Agent 加入，共同梳理和优先排序。

Agent 分工

Agent 组角色具体任务
评估者 Agent（Evaluators）分析 Backlog遍历所有积压项 → 确定是否有人正在处理 → 对无主项分配复杂度评分
执行者 Agent（Executors）代码修复筛选中低复杂度项 → 创建代码变更

信任建设进程

结果

经过持续数月的人机协作磨合，该团队的 Agent 最终独立处理了 500 个 Bug 修复，人类负责人只需关注战略层面的决策。

🧩 六大实践模式提炼

1️⃣
默认公开原则（Public-by-Default）

所有讨论、决策、设计文档放入可检索的公共空间。Agent 只能基于"已写出"的知识工作。私聊 = Agent 盲区。

2️⃣
Agent 角色花名册（Role Roster）

用 Skill 文件定义每个 Agent 的角色、职责边界和工具集。Agent 角色可快速复制，新成员（人或 Agent）加入时明确各自分工。

3️⃣
北极星驱动主动（North Star Proactivity）

人类设定一个宏大目标作为"北极星"。具备此目标的 Agent 会主动提议新工作流，而非被动等待指令。

4️⃣
Doer-Verifier 双重质保（Doer-Verifier）

一个 Agent 执行，另一个 Agent 验证。人类从"执行者 + 审查者"转变为仅做"最终决策者"。

5️⃣
人类注意力预算制（Attention Budgeting）

将人类注意力视为有限预算。Agent 批量聚合问题、重复上下文、控制提审量。可设专用 Agent 进行调度。

6️⃣
自主权递增模型（Progressive Autonomy）

从小任务全审核开始 → 引入 Agent 互查 → 跟踪自主权记录 → 逐步扩大到复杂任务。信任是积累的，不是授予的。

💡 关键收获

🎯 核心洞察

  • Agent 放大的是团队基本功，不是替代它。上下文差、角色不清、无验证机制的团队引入 Agent 只会放大混乱。
  • Agent 需要"眼睛"才能工作。如果信息不在可检索的公共空间，Agent 就是盲人。公开协作文化是 AI 协作的前提。
  • 信任不能一蹴而就。像新人入职一样，从小事开始，逐步授权，反馈循环是必需的。
  • 人类注意力的稀缺性需要被系统化管理。Agent 不仅要完成工作，还要学会"如何与人类高效对接"。
  • Agent 角色可复制、可组合。Skill 文件 + 独立身份 + 工具链 = 可编排的 AI 团队。

✅ 行动检查清单

  • 团队的决策过程是否默认公开且可被文本检索？
  • 每个 Agent 是否有明确定义的角色、工具和权限边界？
  • Agent 是否知道团队的"北极星"目标？
  • 是否有多层验证机制（自动检查 + Agent 互查 + 人工抽查）？
  • Agent 是否被训练将人类注意力视为稀缺资源？
  • 是否有周报复盘机制（含"教训与失误"）？
